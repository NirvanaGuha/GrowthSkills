# Abandon Flow Writer

Cart and browse abandonment are the highest-ROI automation a commerce or SaaS brand can deploy. This skill architects the full sequence — message job, timing, copy, tokens, branches, and sunset — in one run, so a junior operator ships a senior-grade recovery program.

Every sequence is written against the brand's real voice, offer, and proof (from `brand-brain`), not a generic template. CTAs are generated by `cta-variant-generator`. Social proof passages pull from `proof-vault` when present.

---

## Skills this calls

- **`brand-brain`** (required) — loads active brand: voice, banned words, offer mechanics, proof, ICP + awareness tendency, ESP/platform context.
- **`cta-variant-generator`** (required per message) — generates the recovery CTA for each email/push; passes channel, funnel stage (product-aware), and the brand digest.
- **`proof-vault`** (when installed) — pulls real social proof (reviews, star ratings, customer quotes) for message 2 and message 3 objection blocks. Synthesize inline with `[verify]` if unavailable.
- **`subject-line-preview-text-optimizer`** (when installed) — sharpens subject line / preview text pairs per message after copy is drafted. Apply inline if unavailable.

## How a run works

```
Step 0  Load the brand         ──► call brand-brain (voice, offer, ICP, proof, channel context)
Step 1  Qualify the inputs     ──► flow type, trigger spec, product context, platform
Step 2  Architect the sequence ──► apply the Escalating Urgency + Social Proof ladder
Step 3  Write each message     ──► subject / preview / body / CTA (via cta-variant-generator) / token map
Step 4  Spec the branches      ──► converter exits, non-opener re-entries, sunset
Step 5  Self-review + persist  ──► quality checklist, then offer to save
```

### Step 0 — Load the brand (always first)

Invoke the `brand-brain` skill before writing a single word. It returns the active brand digest: voice adjectives, banned words, offer mechanics (free trial / guarantee / discount structure + destination URLs), real proof, ICP + awareness tendency, and any ESP/push platform noted. Use the returned data as the hard override for all copy in this skill. Do not produce any sequence content until `brand-brain` returns.

Fallback: read `~/.brandbrain/brands/.active` + that brand's `brand.md`. If none exists, ask the user to install `brand-brain` or answer a 5-question mini-setup (product + ICP + offer mechanics + 3 voice adjectives + banned words + ESP/push platform).

### Step 1 — Qualify the inputs

Ask for anything not already known. Keep it one message, batched:

| What you need | Why |
|---|---|
| Flow type | Cart abandon, browse abandon, or both? |
| Trigger spec | What event fires the flow (abandoned_checkout, product_page_exit, add_to_cart without purchase)? |
| Product context | Category, price point, key feature or differentiator — needed to write a specific message, not a generic one |
| Platform | ESP (Klaviyo, Braze, ActiveCampaign, etc.) and/or push platform (PushEngage, OneSignal, etc.) — drives token syntax and channel limits |
| Incentive policy | Is a discount/offer available? At which message? Hard "no discount" policy? |
| Sequence depth | How many messages? (default: 3-email + 2-push per flow) |

If a `trigger spec` is not provided, default to standard e-commerce triggers and note assumptions.

## The framework: Escalating Urgency + Social Proof Ladder

Each message has ONE job. The sequence escalates from softest (re-engage intent) to hardest (accept loss), matching the abandoner's cooling commitment at each time window.

| Message | Timing | Job | Primary lever | Urgency level |
|---|---|---|---|---|
| Email 1 | 30–60 min after trigger | Re-engage intent | Helpfulness — remind, not push | None / Very low |
| Push 1 | 1–2 hr after trigger | Pattern interrupt | Specificity + brevity | Low |
| Email 2 | 24 hr | Overcome objections | Social proof + risk reversal | Low–Medium |
| Push 2 | 36–48 hr | Last easy nudge | Convenience / FOMO hint | Medium |
| Email 3 | 48–72 hr | Create urgency + offer | Scarcity / incentive (if policy allows) | High |
| *Sunset branch* | Day 7 (non-converters) | Accept the loss gracefully | Feedback ask / soft re-engagement | None |

**Browse abandonment** uses the same ladder at compressed timing (trigger fires on product-page exit, not cart) and softer language — the commitment was lower; the recovery tone must match.

Timing is a starting point. Flag for the user to adjust per their platform's suppression windows and any existing welcome / win-back flows to avoid message pile-up.

## Craft rules per message

### Email 1 — Re-engage, do not push
- Open with the product name or category, not "You left something behind" (overdone).
- One product image placeholder. Lead with what the product *does for* them, not features.
- No discount yet. If the brand has a guarantee, surface it here naturally.
- Subject line: curiosity or helpfulness angle, not urgency (too soon). Personalization token in subject if the platform supports it.
- CTA: low-commitment. "Pick up where you left off" / "Your [item] is saved" — not "Buy now."

### Email 2 — Overcome objections with proof
- Call `proof-vault` (or synthesize inline with `[verify]`) for the real proof point most relevant to the abandoner's likely objection category (price → ROI/value proof; fit/quality → review quotes; trust → guarantee + return policy).
- Use a specific review quote with real name/source if available; otherwise mark `[verify]`.
- Risk-reversal block: return policy, guarantee, free shipping if applicable. Pull real terms from `brand.md`; do not invent.
- CTA: medium-commitment. "See why [X] customers chose it" or "Check the reviews."

### Email 3 — Urgency + offer (if policy allows)
- Only introduce scarcity if it is real (low-stock signal from platform token) or time-bound (sale ending). Do not manufacture fake urgency.
- If a discount is available: present it once, clearly, with expiry. No "secret code" language unless the brand does it.
- If no discount: lean on consequence framing — what they will not have, not scare tactics.
- CTA: high-commitment. "Get [product] before it's gone" / "Claim your [X]% off."
- Close with a graceful exit line: "If now's not the right time, no worries — we'll be here."

### Push messages
- Title: ≤50 chars, specific to product (use `{{ product_name }}` token or equivalent).
- Body: ≤125 chars. One benefit or proof point. No all-caps.
- Push 1: helpfulness angle ("Still thinking about [product]? It's saved for you.").
- Push 2: softer urgency ("A few people are eyeing the same one. Still yours for now.") — only if real, else drop this and use convenience framing.
- Include click-through URL with UTM tags; note the token syntax for the platform.

### Browse abandon (adapted rules)
- Trigger: product page exit without add-to-cart. Intent was lower — do not write as if they were one click from buying.
- Message 1 job: surface the product in context of the ICP's real goal, not just a reminder.
- Sequence depth: typically 2 emails + 1 push (shorter than cart abandon).
- Tone: warmer, more editorial, less transactional.
- No discount in browse abandon unless the brand's policy explicitly allows it.

## Token map & platform syntax

After writing the full sequence, produce a consolidated token map:

| Token | Purpose | Klaviyo syntax | Braze syntax | PushEngage | Note |
|---|---|---|---|---|---|
| First name | Personalized open | `{{ first_name }}` | `{{ ${first_name} }}` | `{first_name}` | fallback: "there" |
| Product name | Specific message | `{{ event.properties.product_name }}` | `{{ event_properties.${product_name}` | Platform-specific | Required |
| Product URL | CTA link | `{{ event.properties.url }}` | `{{ event_properties.${product_url}` | deeplink | Include UTM |
| Cart total | Message 3 anchor | `{{ event.properties.value }}` | `{{ event_properties.${value}` | — | Cart only |

Adjust syntax to whatever platform the brand named. Note when a token requires a custom event property vs. a profile property.

## Conditional branch logic spec

After the full sequence, produce a compact branch spec:

```
Converter exit:  Any purchase event → remove from flow immediately (all branches)
Non-opener (Email 1): After 48 hr no open → skip to Email 2 on Email 2 timer
Non-opener (Email 2): After 72 hr no open → send Push 2 at compressed timing, then Email 3
Purchased-but-not-this-item: Flag — suppress or move to cross-sell flow?
Sunset (Day 7, no conversion): Short 1-email feedback ask ("Did something stop you?")
                                Unsubscribe / push opt-out honored automatically
```

## Principles

- **Brand-brain first.** No sequence copy before the brand context returns. Voice and banned-words are hard overrides.
- **One job per message.** Escalate the ladder; do not cram all angles into message 1.
- **Specific, not generic.** Name the product, pull real proof, use real offer terms. Generic abandon copy is the commodity to beat.
- **Honest urgency.** Real scarcity tokens, real expiry dates, real stock signals. Do not manufacture fake urgency.
- **Match the commitment to the cooling curve.** Email 1 is helpfulness, not pressure. Email 3 earns the hard ask.
- **Tokens are part of the deliverable.** A sequence spec without a platform-correct token map is incomplete.
- **Browse ≠ cart.** Never use cart-abandon intensity language for a browse trigger.

## What Not to Do

- Do not write any copy before `brand-brain` returns the active brand.
- Do not invent proof, reviews, star ratings, or social proof numbers — use `[verify]` if the brand has no confirmed proof.
- Do not manufacture scarcity ("Only 2 left!") unless the platform sends a real low-stock token.
- Do not duplicate the cta-variant-generator's job — call it; do not freehand a CTA for the button label.
- Do not write browse-abandon copy at cart-abandon intensity.
- Do not omit the sunset/unsubscribe branch — a sequence without an exit is a suppression-list killer.
- Do not use discount language if the brand's offer policy prohibits it; if unsure, ask.
- Do not use emojis or exclamation marks unless the brand's voice explicitly allows them.

## Quality Checklist (self-review before presenting)

- `brand-brain` called and the active brand loaded before any copy was written?
- Flow type, trigger, platform, product context, and incentive policy all confirmed (or assumptions stated)?
- Every message has exactly one job; escalation follows the Escalating Urgency + Social Proof ladder?
- `cta-variant-generator` called for each message's button CTA?
- `proof-vault` called (or inline `[verify]`) for the social proof block in Email 2?
- All personalization tokens listed with platform-correct syntax?
- Browse abandon shorter, softer, and lower-commitment than cart abandon?
- No manufactured scarcity; no invented proof; no discount if policy prohibits?
- Conditional branch logic and sunset path specified?
- Offer to save the sequence to `./sequences/[brand-slug]-abandon-flow.md`?
